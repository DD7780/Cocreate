Removal: verified old/new multi-tab restore, corrupt/quota adversity, deletion-only restore and account isolation, then separately approved legacy-store cleanup.
- SQLite: fresh stores use `2guys1canvas.sqlite`; an existing legacy database remains authoritative until an offline verified copy/cutover. Two competing files fail closed. No live database rename/copy. Owner: local durable store. Removal: stop all writers, retain SQLite/WAL-safe backup, run integrity/hash/receipt checks on a canonical copy, reopen and verify recovery; rollback selects the preserved original, never merges divergent ledgers.

Preserve iframe source checks, CSP, private artifact checks and content hashes. Owner: artifact/preview transport. Prepare exact mappings and access-equivalent copy/rollback evidence in the residual ledger; no resource rename, duplicate namespace or bucket is created here.
