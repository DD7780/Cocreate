## Outcome and boundaries

The original boundary allowed unbounded remote ownership RPCs, slow loss notification and generic/non-actionable non-owner failures. Document appends used unfenced table writes, and durable dispatch intent could complete after a worker lost authority. Equal-revision snapshots only compared claimed hashes. Existing local leases, command receipts, caller scoping and fixed revision promotion were retained.

`RemoteCoordinator` now coalesces claims/renewals, validates epochs, bounds RPC waits to five seconds, rejects delayed/closed ownership and permanently invalidates lost workflows for that process. Ten-second heartbeats renew thirty-second SQL leases. Loss cancels scheduled work, aborts controllers and closes sockets with 1012. Room dispatch rechecks after the awaited accounting write and immediately before provider HTTP; compiled candidates recheck before promotion. Existing SQLite expiry/takeover and candidate revision/fingerprint gates remain. An external request already dispatched cannot be undone; its result may require reconciliation. A timed-out RPC can still finish remotely, but its discarded result cannot authorize the old worker; any orphaned lease must expire.

The existing Worker already targets stable `primary` container affinity with one instance. D-0045 retains that deployment strategy and adds bounded actionable retry when ingress reaches a non-owner. Current membership precedes ownership checks, including before room hydration. HTTP 503 carries Retry-After 2 and redacted safe guidance; WebSocket upgrades use 503 and established lost-owner sockets use 1012. No forwarding/redirect copies bodies, tickets or keys. Unauthorized/viewer checks retain 401/403. Connection diagnosis is bounded to three seconds and existing six reconnect attempts; owner delays clamp to 2-10 seconds. Exhaustion clearly says to reopen, retaining current page edits. Reconnect does not POST commands or infer. Explicit command retries retain participant/request identity and existing durable receipts.

The additive SQL fences canonical snapshots, document updates and dispatch intent under project advisory lock then lease-row lock, rechecking expiry after waiting. Exact revision/sequence replay is inert; conflicting bytes/JSON are rejected even with identical claimed hashes. Stale SQL 40001 invalidates the process. Final provider outcome reconciliation uses the existing ledger without granting dispatch authority. Functions are invoker, blank search path and service-role-only. Application membership remains a separate server check; these trusted-service RPCs do not authenticate browser JWTs.
