## Authority, privacy and recovery

The connection owner explicitly chooses origin, observer and controller UUIDs. Project membership alone gives no session screen/input access. Sessions start owner-private; private login forces owner control, increases the epoch and hides screens/input from teammates. Sharing the resulting authenticated screen requires an explicit owner action. Cookies remain in the disposable isolated profile and never enter snapshots, client responses, downloads, model context or receipts.

One controller, monotonically increasing epochs, serialized durable action IDs and hashed payload receipts precede input. Handoff waits for settled input. Unknown outcomes remain unknown and are never resent automatically. Pause/cancel/disconnect interrupt the executor; owner reopens a fresh unauthenticated browser after process loss, with explicit approval. Expiry and view transport loss close the process. No inference or general agent browser automation is introduced.

Downloads are bounded validated UTF-8 text initially, inert attachment responses with private immutable body references, separate project-reader permission and source/session/command attribution. Private-login downloads require explicit owner publication. Restart preserves saved results and receipts, not cookies/screens or automatic execution. Snapshot compatibility must include the new contract before rollout.
