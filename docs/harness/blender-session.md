## Verified implementation and recovery

Data-only scenes support twelve primitives, three lights, finite colors/scales/locations and one camera. Repository-trusted Python creates a fresh factory-default scene with automatic scripts disabled; supplied code, paths, URLs, imports and existing scene files cannot execute. Each command uses a fresh UUID directory. Capability-free AppContainer and Job Object enforce one active process, 2 GiB, 60 CPU seconds, 120 wall seconds, bounded console/output, explicit task/runtime filesystem access and stripped application credentials. Native ACL mutations are serialized across companions sharing one runtime. Cancellation and cleanup preserve other jobs' grants. Transient temporary-output renames are handled without relaxing the byte ceiling.

Pairing lasts five minutes and is authenticated/single-use. Local CONNECT approves project/owner, executable, separate dedicated workspace, create_scene/save/render and exact observation/control grants. The protected connection credential supports outbound polling, 30-minute connection and ten-minute idle expiry, revocation and local STOP. Network loss cancels after approximately ten seconds. One controller and monotonic epochs fence mutable commands; handoff waits for execution/cancellation acknowledgement. Pause cancels current work; resume/viewer closure never submits or replays.

One exclusive local workspace lease rejects a simultaneous companion/resume before probing or command dispatch. The trusted Windows helper uses an OS [interprocess mutex](https://learn.microsoft.com/en-us/dotnet/api/system.threading.mutex?view=netframework-4.8.1), watches its parent identity, and remains held until the companion has cancelled/settled its executor. Helper loss aborts the connection. A rejected duplicate leaves the current connection untouched. Native acceptance verifies that a second locally approved resume is rejected with no inference/execution while the primary stays connected.

Local receipts are fsynced before launch and after completion. Recorded running IDs reconcile as failed/interrupted without another process; completed receipts can reconcile output upload without another provider call. The coordinator freezes actor/task/spec/submission/requirement/input references, uses the existing physical ledger, validates fixed regular `.blend`/PNG output types/sizes/hashes/evidence, uploads immutable private bodies and commits canonical v3 descriptors under its fence. Failure retains previous successful versions. Latest bodies restore verified into an empty cache; lazy historical reads recheck membership after await. Saved outputs use project permissions independently of session grants. Legacy v1/v2 readers remain explicit; no SQL/bucket change.

Artifacts shows honest background execution/controller/task state, authorized controls, completed rendered previews, independent participant selections, downloads and actionable render reload. Workflow layout and token accounting stay unchanged. Scene appearance still requires human review.
