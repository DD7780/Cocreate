## Boundary and scope

`server/workflow-budget.ts` replaces the memory-only executor counter. Its durable submitted-workflow cycle includes interpretation, initial generation, smaller-task recovery, structured/compilation repair and every transport retry. Each physical HTTP attempt has one call ID, frozen configuration/pricing metadata, scope ID/kind and optional conservative USD reservation. A per-room accounting queue makes admission atomic without adding interpretation concurrency. The coordinator snapshots the scope/reservation plus event projection, awaits ledger acknowledgement, and rechecks current ownership/membership/sponsor authority before HTTP. A failed snapshot acknowledgement fences the coordinator; it cannot continue on an uncertain reset/save.

Twenty-four physical attempts and eight recovery tasks remain unchanged. Counted attempts are never released. Credible measured or nonnegative provider-reported cost replaces a conservative reservation once; unknown/incomplete outcomes retain it. Unknown pricing has an explicit uncertain-call count even when no USD amount can be estimated. Call-ID reuse with different physical identity is rejected; delayed dispatch/unknown records cannot downgrade settled usage. Full-ledger restoration repairs stale active-scope snapshots. No provider-history polling, invoice lookup or paid reconciliation ran.

Retry, supersession, cancellation, model/key reconnect and restart keep the current allowance. A successful fully drained cycle closes it durably; only a later explicit submission/build starts a new cycle. Owner-only `POST /api/rooms/:id/workflow-budget/reset` requires `requestId` and `expectedScopeId`, current membership/coordinator authority and idle work. It stores an actor/request-ID receipt, rejects stale/payload-colliding requests, preserves earlier ledger uncertainty, and performs no inference. Exact replay after restart cannot reset again. Interrupted legacy snapshots whose old allowance was never saved conservatively require this explicit reset. Room state exposes a safe `workflowBudget` summary; no new spending-control UI is introduced.

Each explicit tracked setup operation (connection test, model discovery or capability stage) has a separate named 24-attempt scope, including its own transport/structured repairs. It does not silently consume generation allowances. Temporary BYOK key validation/catalog requests remain generation-free; their pre-existing metadata validation path is unchanged. Hosted temporary BYOK, exact selected models and sponsor permissions are unchanged; no managed/founder fallback, payments or new dollar-limit control is enabled. Existing frozen configured limits are enforced by physical admission, replacing the competing logical reservation gate. Active scopes retain their original dollar limit when settings change; a closed cycle uses the future configured limit for its next explicit build without erasing the old history. Focused assertions cover both cases.

Changed files: `server/workflow-budget.ts` holds scope admission/reconciliation; `server/rooms.ts` persists and restores it, assigns setup scopes and implements reset; `server/index.ts` authorizes the reset route; `server/providers.ts` validates reported cost; `server/usage-ledger.ts` and `src/types.ts` expose safe accounting. New budget tests/fixtures and affected preset/progress/reliability/baseline assertions cover the changed boundaries. Canonical steering, D-0051, Graphify and the Step 08 artifact directory carry the contract and evidence.
